rules & sync, local storage & secrets, untrusted input (CSV/backup/files), and
platform/build/CI. Every finding is tracked as a GitHub issue labelled `audit`.

## Verdict

Overall posture is **strong**: no committed secrets (history clean), no SQL
injection (Room `@Query` binding only), R8 + obfuscation on for release, ATS
secure by default on iOS, CI has no `pull_request_target` and forks get no
secrets, and the offline flavor is exemplary (network permissions stripped and
enforced by a build-time manifest verifier).

One real isolation hole (HIGH) plus a set of defense-in-depth gaps. Nothing
blocks development, but **#152 should be fixed before relying on the rules for
tenant isolation**.

## Suggested order

1. **#152** — the only finding that breaks the data-isolation model.
2. **#153 + #154** — cheap, stop financial data / PII leaving the device.
3. **#155, #156** — untrusted-input and sync robustness.
4. **#158, #164** — supply-chain pinning.
